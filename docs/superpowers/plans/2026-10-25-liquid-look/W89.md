## Ward W89: Text dissolves like ink

**North star:** step 5, visual only. Where Merge's and the card's liquids mix, the labels dissolve into ink in both renderers instead of being cut (WebGPU, D79-1) or floating crisp over the liquid (Canvas2D). The re-form within 3 s, the pixel-identical rest and the slice matrix are unchanged. Whether "the labels never overlap" needs a note is D89-4.

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or superpowers:executing-plans. WDD / GS-TDD as every ward. **This plan is written in two parts, as W88's.**
> - **Part 1 (this file now) is W89.0:** the epic row, the ward file, the baseline, the spike record (spike W89.0 is already done) and the direction gate.
> - **Part 2 (W89.1 red … gold)** is written after the gate, against the approved decisions, and presented to Dennis before red.

**Goal:** when two elements' liquids meet and mix, the text in the mixing zone dissolves like ink in water: it flows out, softens and drifts with the liquid. When the liquids separate and come to rest, the text is crisp again, exactly as today. Splash, shake, drag without contact, scroll and gravity look exactly as today.

**Architecture:** spike variant C. Each particle carries an ink colour (the mean premultiplied atlas texel over its rest cell). The ink is splatted with the density kernel into Σw·ink next to Σw and Σw·id. Per pixel (WebGPU texel, Canvas2D cell): lo/hi = smallest/largest element id, p = (Σw·id/Σw − lo)/(hi − lo), mix = 4p(1 − p), fade = smoothstep(0.03, 0.3, mix), and the output text is crisp × (1 − fade) + ink × fade. WebGPU adds the ink and Σw·id targets to the existing text pass and resolves in the text composite. Canvas2D gets the text atlas and uses `liquid-text` to hide the DOM text of a mixing element while it draws that element's atlas text and the ink. Rust, the FFI and the public API are untouched.

**Tech Stack:** TypeScript (strict), WGSL, Canvas2D, Vitest 4 (jsdom, fake canvas, fake GPU), Playwright 1.63.0 (canvas2d blocking in CI; WebGPU local on Metal).

**Spec:** [`2026-11-02-liquiddom-ink-design.md`](../../specs/2026-11-02-liquiddom-ink-design.md) (approved by Dennis 2026-11-03; brainstorm saga mem_20261031_07c6640a). It is binding for this ward, including §9 (the author's calls, which the gate may change). Spike report: `.superpowers/sdd/W89/spike-report.md`.

**WebGPU text pass** (`renderers/webgpu/webgpu-renderer.ts`, 1367 lines; `shaders.ts`, 662 lines)
- Formats (`webgpu-renderer.ts:66-81`):
  - T0 `rgba16float` + T0a `r16float` at `t0Scale` (0.5).
  - The text pass's targets, all at 1× the backing size:
    - T1 `rgba16float` (Σw·text_rgba_premul, `:69`);
    - T1w `r16float` (Σw, `:70`);
    - T1id `rg16float` (smallest id, minus largest id; `MIN_BLEND`, `:77`, `:81`).
  - Atlas `rgba8unorm` (`:71`).
  - `TEXT_ID_EMPTY = 4096` (`:79`), exact in f16 and above every slot id, because `maxElements ≤ 256` (`options.ts:102`).
- **Bytes per sample today: 8 + 2 + 4 = 14 B** of the 32 B `maxColorAttachmentBytesPerSample` default (3 of 8 attachments).
  - The spike added `rgba16float` ink + `r16float` Σw·id: 14 + 10 = **24 B**, 5 attachments.
  - `r32float` for Σw·id would make it 28 B (the r32 alignment to 4 included). It is still under 32 B, but `r32float` is not blendable in core WebGPU: it needs the `float32-blendable` feature (`:75` says so). Today `requestDevice` asks for no features (`:568-569`).
- Memory: every extra full-resolution byte per sample costs ≈ 4.1 MB at 1280 × 800 × DPR 2. The spike's +10 B is ≈ +41 MB on top of today's 14 B (≈ 57 MB).
- The pipeline and its pass:
  - The text pipeline's targets are at `:246-260`.
  - The pass descriptor holds `[t1, t1Weight, t1Id]` (`:489-492`).
  - The pass is encoded after the splat and the shadow passes, only when `drawText` is set (`:693`, `:706-714`).
  - `allocateTextTargets` (`:1198`) creates T1/T1w/T1id. T1id gets `COPY_SRC` for the W79 hook.
- **The atlas is fragment-only.** `textLayout` binding 6 (atlas) and 7 (sampler) have `visibility: F` (`:203-204`).
  - Particles sample it per fragment at `rest_uv + F⁻¹·d / size` (`shaders.ts:361-377`).
  - Spec §3 needs the atlas visible to the vertex stage for the per-particle ink.
  - The spike sampled 16 taps per vertex, which is 6 × 16 per particle per frame, because the quad has 6 vertices. The ink changes only per generation or atlas version (spec §2).
- **Only text-carrying moving elements enter the text pass.**
  - The vertex shader skips inactive elements, elements at rest (`rest_alpha >= 1`) and elements without a valid text record (`shaders.ts:317-323`, `info.size.z < 0.5`).
  - The pass runs only when `hasMovingText` (`gpu-buffers.ts:147`, called at `webgpu-renderer.ts:1004`).
  - So T1w, T1id and the spike's Σw·id see no text-less liquid. Spec §9 requires a text-less liquid to count, which goes beyond what the spike built (D89-3).
- **W79's id gather (D79-1, `.wdd/wards/ward-079.md:35-38`):**
  - Every fragment the kernel covers writes `(id, −id)` with min blending (`shaders.ts:375`).
  - The text composite gathers the 2×2 footprint (`shaders.ts:414-417`) and sets `coverage = 0` where `lo + 0.5 < hi` (`:418-419`). This is the hard cut that W89 replaces with the fade.
- `textReady(id)` (`webgpu-renderer.ts:817`) is true while the device is alive, the atlas is confirmed and the slot's record is valid. The runtime's `liquid-text` follows it (D74-6).

## Global Constraints

- **Renderer only:** TypeScript/WGSL rendering. No Rust, FFI or public-API change, and no new option (spec §1, §6).
- **Unchanged otherwise:** see the [README](README.md). Rendering never touches the DOM; the runtime owns every class write.
- **Anti-goal (Dennis):** "it must not look like pixel noise instead of ink." Variants A (point dabs) and B (dabs + blur) are ruled out (spec §1).
- **Spike level:** the zone is not strengthened or widened beyond the spike's level ("det er ok"). It is a narrow band during a still hold and spreads over the moving blob during movement (spec §1).
- **Only when two liquids meet:** splash, shake, drag without contact, scroll and gravity look exactly as today, including WebGPU text tearing with its own liquid (spec §1).
- **At rest:** pixel-identical to today (spec §2). Nothing persists between frames.
- **Canvas2D cost:** +2 ms at 6 elements on a quiet machine, measured interleaved against today (spec §4, §9). A coarser ink grid (e.g. 4 px) is allowed if vision still says ink.
- **WebGPU cost:** at most +1 ms of GPU time at 6 elements × DPR 2 where timestamp queries exist, otherwise the CPU frame time within W88's 3.76 ms threshold (spec §9).
- **Reduced motion:** no ink (spec §5). Print and forced colours show the DOM text as today.
- **a11y:** the DOM text stays in the accessibility tree; `liquid-text` keeps its fail-safe paths in both renderers (spec §4, §5).
- **No text, no cost:** an element without text has no atlas text, no ink and no cost, and an instance whose elements have no text builds no atlas (spec §5, §9).
- **Spike rule (D2):** `spike/w89-ink` is reference only. Its code is never copied; it may be read to locate code paths.

## Part 2

Written as W89.0 Step 6, after the gate, against `4e741b1`, revised in fix round 1 after a plan review (every `Decision:` line approved 2026-11-03, all as recommended). **Proportion rule:** the red tests of W89.1 are its deliverable and are written out in full; W89.2 … W89.6 give files, exact signatures, the values the decisions pin, the red rows they turn green, the command and its expected output, and a code block only where the signature and the tests leave the algorithm open (the Canvas2D frame, the WGSL resolve).

**Architecture.** One pure module holds the ink maths and the tunable constants (`renderers/ink.ts`); the WGSL interpolates the constants.
- **WebGPU** keeps one text pass and widens it: T1ink (`rgba16float`, Σw·ink) and T1mix (`rg16float`, r = Σw·rank, g = the all-liquid Σw) join T1/T1w/T1id (26 B per sample). Every moving element enters the pass; a text-less one writes T1id and T1mix only, so T1w stays text-only. The vertex stage samples the atlas over the particle's rest cell (the per-particle ink). The text composite maps W79's gathered lo/hi ids to ranks through the element records (`EG.RANK`), takes fade = smoothstep(0.03, 0.3, 4p(1 − p)) and returns `crisp × (1 − fade) + ink × fade`; D79-1's cut is gone.
- **Canvas2D** gets the atlas lazily: the renderer reports `wantsAtlas()` once two elements move, and the runtime builds the page on the next frame. A dedicated `InkCanvas2D` (`renderers/ink-canvas2d.ts`) splats every moving particle into its own monomorphic `InkGrid` (Σw, Σw·rank, lo/hi rank, Σw·ink) only when two elements move and one of them has atlas text. It resolves fade and ink per cell, steps the `MixReport` hysteresis per slot, and draws after the resting rects: the ink, and for each slot it reports, the atlas text at the element's DOM box with 1 − fade cut out. `textMixing(id)` says what the last render drew; under Canvas2D the runtime's `liquid-text` follows it.
- **Runtime:** reduced motion and a stop repaint the canvas once with `suppressText` where a text class was held (W88's repaint, widened); the device-lost rebuild keeps the atlas. Rust, the FFI and the public API are untouched.

**Design resolutions this plan makes.** Resolutions 2, 4, 13 and 14 extend an approved decision or approved tests, and resolution 15 sets A1's bound; W89.1 Step 0 presents them before any red test.
1. **The class follows what was drawn.** Canvas2D decides the report from frame N's cells and draws a reported slot's atlas text and ink from frame N + 1; `textMixing(id)` is "the last render drew it", and the toggle runs after `render()`. Entry therefore lags one frame (D89-6: ≤ 2), and the class and the canvas text always change in the same frame.
2. **"Dragged" means W78's away set (extends D89-6).** The report skips a slot while it is DRAGGED **or** while this instance holds `liquid-away` on it (released, crawling home), read from `RenderFrame.awaySlots`. Without it, Merge after the release would report mixing and the canvas would draw its atlas text at its DOM box while its liquid is still away. D89-6's reason ("its label is already hidden by W78's `liquid-away`") covers both.
3. **Ink only where the DOM text is hidden.** A particle feeds the ink grid's Σw·ink only while its slot is drawn (resolution 1) or away; every moving particle feeds Σw, Σw·rank and lo/hi. A cell counts toward the report for its smallest and its largest rank only: with three liquids in one cell the middle one is not counted there, because p (and so the fade) describes the lo|hi pair; the middle element is counted at its own interfaces with each neighbour, where it is lo or hi, so a three-way mix still enters through those cells.
4. **A stop repaints without text (extends D89-10 to the stop path, Review Focus 1).** W88's `repaintWithoutShadows` becomes one repaint with `suppressShadows` and `suppressText` whenever a shadow class or a text class was held. It runs on a stop (a failed frame or a failed rebuild) and when reduced motion turns on while paused. Under WebGPU this also removes the liquid text a stopped canvas kept until now.
5. **Per-particle ink in the vertex stage (D89-2's builder choice).** 16 taps × 6 vertices per particle, no new buffer or pass. W89.6 Step 3 measures the GPU time; over +1 ms, the cached per-particle buffer of D89-2 replaces it (a note, no new decision).
6. **T1w stays text-only:** `out.acc_w = w * in.has_text;` the all-liquid Σw lives in T1mix.g (D89-3's separate Σw).
7. **Rank map.** `packElements` writes the dense rank of every drawable slot with restAlpha < 1 and mass > 0 into `EG.RANK` (0 elsewhere; existing records keep their zeros). The composite reads `elements[lo].rank` and `elements[hi].rank`, so T1id, `TEXT_ID_EMPTY` and A8 are untouched.
8. **`captureTextIds(opts?: { mix?: boolean })`.** Only `{ mix: true }` also copies T1mix and returns `mix` and `ranks`, so W79's capture and its four tests stay as they are; the acceptance hook asks for it.
9. **`INK_ALPHA_CAP` starts at 0.6** (the spike's suggestion; D89-11 allows weaker). The amended A1 needs it: at fade ≥ 0.9 the crisp text weighs ≤ 0.1, and with ink alpha ≤ 0.6 no zone pixel can reach W79's text threshold (200).
10. **The ink grid is the density cell** (`INK_CELL_FACTOR = 1`); D89-9's 4 px fallback is factor 2.
11. **Canvas2D draws ink and atlas text after the resting rects**, above all liquid, as the DOM text it replaces sits.
12. **The lazy atlas.** `atlasWanted` is set after a render whose renderer reports `wantsAtlas()` (Canvas2D only) and stays set; it also arms `atlasDeferred`, so the next frame builds the page. The device-lost rebuild keeps `atlasRects` and `atlasFrame` and sets `atlasWanted` when a page existed (D89-5).

14. **`unobserve(el)` repaints without that element's text (extends D89-10's repaint, Review Focus 1).** When this instance holds `liquid-text` on `el`, `unobserve` releases the class and repaints once, paused or running, with `RenderFrame.textOff = id`: Canvas2D draws no atlas text and no ink for that slot; WebGPU writes a zeroed text record for it for that render (the next pack restores it; `textReady` keeps its answer) and skips the pass when no other text moves. /** IEEE half rounding (nearest, ties to even): what one additive blend into an f16 target keeps. */
function f16(v: number): number {
  if (v === 0 || !Number.isFinite(v)) return v;
  const step = 2 ** (Math.max(Math.floor(Math.log2(Math.abs(v))), -14) - 10);
  const [q, lo] = [v / step, Math.floor(v / step)];
  return (q - lo > 0.5 || (q - lo === 0.5 && lo % 2 !== 0) ? lo + 1 : lo) * step;
}

}

/** Reduced-motion media query stub (text-runtime.test.ts pattern); install before setup(). */
function stubReducedMotionMedia(): { fire(matches: boolean): void; restore(): void } {
  const listeners = new Set<Listener>();
  const add = (_t: string, cb: Listener) => listeners.add(cb);

  const rm = { matches: false, media: "(prefers-reduced-motion: reduce)", onchange: null, addEventListener: add, removeEventListener: del, addListener: (cb: Listener) => listeners.add(cb), removeListener: (cb: Listener) => listeners.delete(cb), dispatchEvent: () => true };
  const other = { ...rm, addEventListener() {}, removeEventListener() {}, addListener() {}, removeListener() {} };
  const original = window.matchMedia;
  const value = vi.fn((q: string) => (q.includes("prefers-reduced-motion") ? rm : { ...other, media: q }));

  return {

      rm.matches = matches;
      for (const cb of [...listeners]) cb({ matches });

    restore: () => Object.defineProperty(window, "matchMedia", { configurable: true, writable: true, value: original }),

/** IEEE half bits of a normal, non-negative number (round to nearest). */
function half(v: number): number {
  if (v === 0) return 0;
  const e = Math.floor(Math.log2(v));
  const m = Math.round((v / 2 ** e - 1) * 1024);
  return m === 1024 ? ((e + 16) << 10) : ((e + 15) << 10) | m;
}
const neg = (h: number): number => h | 0x8000;
const EMPTY = half(4096);

/** A 3 × 2 capture with 256-byte rows: ids[y][x] = [lo, hi] (null = empty), mix[y][x] = [Σw·rank, Σw]. */
function capture(ids: Array<Array<[number, number] | null>>, mix: Array<Array<[number, number]>> | null, ranks: number[] | null): InkCaptureLike {
  const data = new Uint16Array(128 * 2);
  const m = new Uint16Array(128 * 2);
  ids.forEach((row, y) =>
    row.forEach((t, x) => {
      data.set(t ? [half(t[0]), neg(half(t[1]))] : [EMPTY, neg(EMPTY)], y * 128 + 2 * x);
      const [r, g] = mix?.[y]?.[x] ?? [0, 0];
      m.set([half(r), half(g)], y * 128 + 2 * x);
    }),
  );
  return { textPass: true, width: 3, height: 2, bytesPerRow: 256, empty: 4096, data, ...(mix ? { mix: m } : {}), ...(ranks ? { ranks } : {}) };
}
