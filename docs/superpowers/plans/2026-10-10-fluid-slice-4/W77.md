**The grid rule, precisely.** For each frame the renderer takes `maxR = max(kernelRadiusPx(paint.spacingPx))` over the frame's defined paints (resting or moving: the cell must not flip while elements start and stop moving). With no paint it keeps its cell. The cell is `densityCellPx(maxR) = max(DEFAULT_SCALE_PX = 2, ceil(min(maxR, 16)) / 4)` CSS px, so the kernel spans at most 4 cells per radius, as R = 8 px did on the 2 px grid; quarter-px steps (`ceil(R)/4`) keep the grid from reallocating on sub-pixel spacing changes. When the cell differs from the current one, the renderer builds a new `DensityGrid(cell)` and resizes it, the density canvas and its `ImageData` to the last CSS size; it never reallocates otherwise. Acceptance: R 7.09–7.36 → 2 px (identical frames); landing: R 12.47 / 13.04 → 3.25 / 3.5 px (the paints' maximum, 13.04, gives 3.5 px); R 16 → 4 px. The splat footprint stays ≈ π·(R/cell)² ≈ 44–50 cells; the whole grid shrinks with cell², so `clear()` and `writeImage()` get cheaper too.
