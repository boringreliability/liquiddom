**Design resolutions this plan makes (within the approved decisions; presented with the plan):**
1. **The offset at the fire is the finger's (0, 0) plus the scroll.** The fire moves the down point to where the finger rests (`x0 += cx`), so the liquid never jumps by the up to 8 px the finger drifted while holding, and later moves count from there; the scroll since the down point (W80 `scrolled()`) stays in the offset (W84.0 Q4: a scroll during the pending press carries into it).
2. **A child's `lostpointercapture` is not the drag's.** A touch press is implicitly captured by its target; when the fire captures the observed ancestor (a press on the card's heading), the heading loses its capture and that event bubbles to the card. `onLost` now ends the drag only when the event's target is the dragged element itself. Mouse and pen have no implicit capture, and W78's tests dispatch on the element: unchanged. Chromium did not need it in the plan validation (row 28 passes without it); it follows the Pointer Events spec for a browser that fires the child's `lostpointercapture`, pinned in jsdom by row 14.
3. **`drag` per instance.** Each instance follows its own option (the registry record, captured on that instance's first `observe()`). Two instances observing one element with different `drag`: the draggable one drags its own liquid and prevents its own `touchmove` and `contextmenu`; the opted-out one does nothing. The callout rule is suppressed while any observing instance drags the element: the registry holds `data-liquid-drag="off"` only while every observing instance opted out (`holdDragMode`/`releaseDragMode`, refcounted per element like the decoration; the author's own attribute is restored by the last release). An element observed without the option gets no attribute, so the DOM of every W83 test and baseline is unchanged.
4. **`contextmenu` listens on the document while a press is live** (with `selectstart`/`dragstart`) and prevents only for a touch press; a mouse right-click starts no press, and an opted-out element never has one.
5. **`idleDecay` of a zero, negative or non-finite frame is 1** (no decay). W68 decayed ×0.8 per sample even at Δt 0; the runtime never samples twice at one time (the manual clock's `advance(0)` renders no frame), so nothing measured changes.
6. **The touch e2e runs the acceptance scene on the RAF clock** (live, as on a phone) and follows the spike's harness rules: its own `gotoTouchScene` polls with `expect.poll` (`gotoScene` uses `waitForFunction`), interventions are read with a `ReportingObserver` init script, no CDP `Log.enable`. The scene's `?nodrag=split` is parsed in `acceptance.ts` itself (not `scene-params.ts`, whose tests stay as they are) and re-observes through the public facade, so the option is validated as an author's would be.
7. **No Linux baseline moves, none is added.** The callout rule paints nothing and an element without `drag` gets no attribute; at 60 Hz the decay is bit-identical (vitest 15). W84.4 runs the Docker Canvas2D suite without `--update-snapshots`.

**Review Focus** (the five failure modes most likely to slip past the happy path, each pinned by named tests; numbers are rows of the ward's `## Tests` table):
1. **No long-press timer outlives its press.** A timer left by `destroy`, `unobserve`, reduced motion, blur, `pointercancel`, `pointerup` or a swipe past 8 px would start a drag on a dead press (or a destroyed instance) 350 ms later. Every end path goes through `end()`, which clears it. Pinned by vitest 5 and 25 (`vi.getTimerCount()` 0 after each path, nothing drags 1 s later).
2. **A second finger never starts or disturbs a drag.** A non-primary `pointerdown` must start nothing, and its moves, `pointerup` and `pointercancel` must leave a pending or live drag of the first finger untouched. Pinned by vitest 8.
3. **`drag: false` nested in a draggable element drags nothing.** The opted-out inner element must still claim the `pointerdown` (else the outer one drags for it), for mouse, pen and touch, without preventing selection. Pinned by vitest 13, 24 and e2e 31.
4. **The context menu is suppressed only for a live touch press.** A blanket `contextmenu` block would kill desktop right-click; a missing one opens Android's menu mid-drag. Pinned by vitest 12, 22 and 24 (Chromium's emulation never fires it on a hold: the phone smoke checks it for real).
5. **`touchmove` is prevented only while a touch drag is live, and its listener exists exactly from `observe()` to `unobserve()`/`destroy()`, never on an opted-out element.** Preventing a pending press's moves would block every swipe that starts on an observed element; a listener added late is ignored by iOS Safari. Pinned by vitest 10, 11, 22, 24 and e2e 27 (no scroll, no `pointercancel`, no intervention) and 29 (a swipe still scrolls).

Also pinned (must cover, not in the five): D84-3's bit-identity at 60 Hz and the equal 120 Hz tail (vitest 15–17); a scroll during a pending press carries into the offset and does not cancel it (vitest 9); a child's lost implicit capture (vitest 14) and a touch drag started on a child in Chromium (e2e 28).

/** 300 px/s built at t = 1/60 s (both rates sample that move at the same time), then 1 s of idle frames at `hz`; vx at every 60 Hz frame time. */
function idleTail(hz: 60 | 120): number[] {
  const t = new PointerTracker();
  const dt = 1000 / hz;
  let now = 0;
  t.move(0, 0);
  t.sample(now, ORIGIN);
  t.move(10, 0);
  now = FRAME_MS;
  expect(t.sample(now, ORIGIN).vx).toBe(300);

    now += dt; // the manual clock accumulates (clock.ts)
    const vx = t.sample(now, ORIGIN).vx;
    if (k % per === 0) out.push(vx);
  }
  return out;
}

/** Installs `window.__w84` before any page script. */
export async function installTouchProbe(page: Page): Promise<void> {
  await page.addInitScript(() => {
    const probe = { cancels: 0, clicks: 0, interventions: [] as string[] };
    (window as unknown as { __w84: typeof probe }).__w84 = probe;
    document.addEventListener("pointercancel", () => {
      probe.cancels += 1;
    }, true);
    document.addEventListener("click", () => {
      probe.clicks += 1;
    }, true);
    type Report = { type: string; body?: { message?: string } };

/** touchStart at `at`, a still hold of `holdMs`, then `steps` moves of `stepPx` (y) 16 ms apart; the finger stays down. */
export async function longPressMove(page: Page, cdp: CDPSession, at: { x: number; y: number }, index: number, holdMs = HOLD_MS, steps = STEPS, stepPx = STEP_PX): Promise<LongPressRun> {
  const scroll: number[] = [];
  let draggedSeen = false;
  await touch(cdp, "touchStart", at.x, at.y);
  await page.waitForTimeout(holdMs);
  for (let i = 1; i <= steps; i++) {
    await touch(cdp, "touchMove", at.x, at.y + stepPx * i);
    await page.waitForTimeout(16);
    scroll.push(await scrollY(page));
    if ((await slots(page))[index]!.interaction === DRAGGED) draggedSeen = true;
  }
  await page.waitForTimeout(50); // a frame or two for the last offset
  return { scroll, mid: await slots(page), draggedSeen };
}

/** A quick swipe: `steps` moves of `stepPx` (y) 16 ms apart starting at `at`, then the release. */
export async function swipe(page: Page, cdp: CDPSession, at: { x: number; y: number }, steps = 6, stepPx = -5): Promise<void> {
  await touch(cdp, "touchStart", at.x, at.y);
  for (let i = 1; i <= steps; i++) {
    await touch(cdp, "touchMove", at.x, at.y + stepPx * i);
    await page.waitForTimeout(16);
  }
  await touch(cdp, "touchEnd");
}

 * - touch (W84, D84-1): a real LONG_PRESS_MS timer starts; more than TOUCH_SLOP_PX of the finger's
 *   own motion, pointerup or pointercancel before it fires end the press (the page scrolls, a tap

    }

      d.removeEventListener("dragstart", this.onSelect);
      d.removeEventListener("contextmenu", this.onContextMenu);

    }

    if (this.longPressTimer === null) return;
    clearTimeout(this.longPressTimer);
    this.longPressTimer = null;
  }

  private end(how: DragEnd): void {

    if (p === null) return;
    this.press = null;
    this.clearLongPress(); // W84 (D84-1): no timer outlives its press
    this.listen(false);

    p.el.removeEventListener("lostpointercapture", this.onLost);
    this.armSwallow(p.el);
    if (how === "release") {
      this.scheduleClear(); // the click follows this pointerup in the same task

      this.cancelledPointerId = p.pointerId;

      if (typeof p.el.hasPointerCapture === "function" && p.el.hasPointerCapture(p.pointerId)) {
        try {
          p.el.releasePointerCapture(p.pointerId);
        } catch {
          // Already released.
        }
      }
    }

  }

  private armSwallow(el: HTMLElement): void {
    this.clearSwallow();
    this.swallowEl = el;
    this.win.addEventListener("click", this.onClickCapture, true);
    this.win.addEventListener("pointerdown", this.onStale, true);
    this.win.addEventListener("keydown", this.onStale, true);
  }

  private scheduleClear(): void {
    if (this.swallowTimer !== null) return;
    this.swallowTimer = setTimeout(() => {
      this.swallowTimer = null;
      this.clearSwallow();
    }, 0);
  }

  private clearSwallow(): void {
    if (this.swallowTimer !== null) {
      clearTimeout(this.swallowTimer);
      this.swallowTimer = null;
    }
    if (this.swallowEl === null) return;
    this.swallowEl = null;
    this.win.removeEventListener("click", this.onClickCapture, true);
    this.win.removeEventListener("pointerdown", this.onStale, true);
    this.win.removeEventListener("keydown", this.onStale, true);
    this.doc.removeEventListener("pointerup", this.onUpAfterCancel, true);
  }

### Touch and opt-out (Ward 084)

- **Long-press (TS, `drag-tracker.ts`, D84-1):** a primary touch `pointerdown` on a draggable observed element (the innermost one) starts a real `LONG_PRESS_MS` (350) `setTimeout`; the finger's own motion past `TOUCH_SLOP_PX` (8), `pointerup` (a tap stays a click), `pointercancel`, blur, Escape, `unobserve`, `destroy`, reduced motion and a detached element end the press, and every end clears the timer. ### Drag

Press an observed element with the mouse or a pen and move more than 4 px: its liquid follows the pointer while the element itself stays put, and flows home on release. On touch, hold the element for 350 ms, then move: the liquid follows the finger and the page does not scroll. Moving more than 8 px before that is an ordinary scroll, and a tap is an ordinary click. The click that ends a drag is swallowed. While a finger holds a draggable element, its long-press menu is suppressed, and draggable elements get `-webkit-touch-callout: none` (no iOS callout or link preview). Escape, `pointercancel`, blur, `unobserve()` and `destroy()` cancel a drag; under reduced motion nothing drags; the keyboard never drags.

```ts
liquid.observe(el, { drag: false }); // never drags (mouse, pen or touch); keeps the browser's long-press menu
```

`drag` is read once, like `viscosity`; a press on an opted-out element never drags an observed ancestor either.
