**Architecture:** Rust gains one scalar call, `FluidCore::set_area_hint(area_px2, max_element_h_px) -> bool`: while `generation() == 0` it rebuilds the grid exactly as the constructor would have for that hint (B5 cell, B15 margin, the grid's current world, the viewport kept), replays the scroll applied before it on the new lattice (`Grid::scroll_origin`), invalidates the fused AABB and rewrites the dynamic view; from the first `redistribute()` on it returns `false` and changes nothing. The runtime calls it once per instance, in the redistribute batch, when `create()` had hint 0 and the batch's observed area is > 0 (a batch with area 0 skips its redistribute while the hint is pending, so the generation stays 0), before `core.redistribute()`. TypeScript's three stop paths become one: `rebuildFailed` calls `stopInstance(msg, err)`, which guards against a second stop and ends with the new `onError(err)` (caught, last). The facade passes `onError` through the option whitelist. The React and Vue providers (and the Vue plugin) chain their own handler in front of `config.onError`: it destroys the stopped instance synchronously, empties `useLiquid()` and sets the new `useLiquidError()`; a `create()` rejection sets the same error. `pickElementOptions` copies every defined key, so `drag` reaches `observe()`; `<LiquidElement drag>` is a consumed prop in both adapters. `examples/vue` (render functions in `.ts`) joins `examples/react`; both give their `LiquidElement` pill `drag={false}`, show the error state, and `e2e/dist.spec.ts` serves both built examples.

**Design resolutions this plan makes (within the approved decisions; presented with the plan):**
1. **`onError` is the last thing `stopInstance` does, so `destroy()` from inside it is safe** (the controller's resolution). Every stop path (`frame()`, `growWorld()`, `rebuildFailed`, design resolution 7) returns right after `stopInstance`, and `rebuildAsCanvas2D`'s success path already checks `failed` after `resizeCanvas()`. Pinned at the runtime (`resize_world` throws, the handler calls `rt.destroy()`) and the facade (a frame throws, the handler calls `inst.destroy()`, the element is restored exactly): rows 9 and 10.
2. **The providers destroy the stopped instance synchronously, inside the handler** (not in a microtask). The core calls `onError` last in the stop, so the instance is already inert; destroying it at once restores the elements in the same task, `useLiquid()` never hands out a stopped instance, and nothing can observe it in between. React 18 batches a `setState` from a RAF or event callback, so the state change costs one render. StrictMode is pinned: the dev effect replay creates two instances, the first is destroyed by the replay's cleanup, a stop of the second leaves one error and no third `create()` (row 22).
3. **The examples document the error state and the gold smoke forces a stop from devtools, with no hook in any package.** Each example renders `Liquid stopped: <message>` (`role="alert"`) while `useLiquidError()` is set. To force a real stop, Dennis runs one line in the browser console: `document.querySelector(".liquid-element").getBoundingClientRect = () => { throw new Error("forced stop") }`. The runtime's `registry.sync()` reads every observed element's rect each frame, so the next frame throws: the real throwing-frame path, its `console.error`, `onError`, the provider's destroy and the error line. Nothing in `liquiddom`, `@liquiddom/react` or `@liquiddom/vue` changes for it.
4. **While the hint is pending, a batch whose observed area is 0 skips its `redistribute()`; the first batch with area > 0 clears the flag (whatever `set_area_hint` returns) and redistributes as before** (review M10, replacing the first draft's "the flag survives, the generation does not"). A batch with area 0 has nothing to place (every weight is 0, so `pool::redistribute` would place no particle), so skipping it changes nothing visible; it keeps the generation at 0, so an app that observes hidden elements first (`display: none`, a closed tab) or whose first batch only unobserves still gets the hinted cell at its first batch with area. Nothing else reads such a batch: the over-budget check has nothing to check at area 0, the bridge sees no generation change (no paints are built for elements without area, and no particle is placed), and the next batch with area redistributes every observed slot at once. A core created with a hint never skips. Pinned by row 14.
5. **No Linux baseline moves.** Every Linux baseline is the acceptance scene (`a11y`, `acceptance`, `modes`), which creates with `autoObserve` and four `[data-liquid]` candidates: hint > 0, no call, bit-identical to W84 (row 13 pins that a hinted core never calls). The scenes that create without candidates now take the hinted cell at their first batch: `scroll-container.html` (`scroll.spec.ts`, W80 container scroll), `long-page.html` (`parking.spec.ts`, `perf.spec.ts`), `under-page.html` (`under-page.spec.ts`), `splash.html` (`scenes.spec.ts`), `stress.html` (`multi-instance.spec.ts`, perf), `smoke/webgpu-modes.html` (`webgpu-robust.spec.ts`, webgpu-hw only). None has a screenshot baseline; their numeric checks were re-run in the plan validation (Plan validation below) and none needed a changed bound.
6. **The core replays the scroll applied before the first batch, not the origin's drift.** The drift after a scroll `D` is `−rem(D, cell)`; re-splitting the old drift with the new cell gives `rem(rem(D, 8), c)`, which differs from a hinted core's `rem(D, c)` (e.g. `D = 10`, `c = 6.17`: 2 px against 3.83 px of lattice phase). `FluidCore` therefore keeps the sum of the sanitised scroll deltas while `generation == 0` (`pre_place_scroll_px`, f64; a hinted core keeps it too and never reads it) and `set_area_hint` feeds it to the new grid's `scroll_origin`, so the lattice phase equals a hinted core's with the same scroll history up to f32 rounding (row 43 measures the bound).
7. **A throwing `set_area_hint` stops the instance like a throwing `resize_world`.** It allocates the new grid (up to ≈ 55 MB at an 8192 px world); an allocation failure would otherwise escape the microtask uncaught and leave a poisoned core running. The batcher catches it, calls `stopInstance("[liquiddom] rebuilding the grid for the area hint failed; the instance stopped. Call destroy() and create a new instance.", err)` and skips the redistribute, so `onError` covers it as every other stop. Pinned by row 16. (A fourth stop path inside D85-1's rule "every stop"; ask Dennis to confirm.)
8. **`pickElementOptions` copies every own key whose value is defined, not a fixed list.** A key core adds later reaches `observe()` without an adapter change (the W84 gap this ward closes), and an unknown key gets core's `TypeError`, exactly as a direct `observe()` would. `<LiquidElement>` only ever passes `viscosity`, `recovery` and `drag`.
9. **An `onError` in `config` that is not a function is passed on unchanged**, so `create()` rejects with core's `TypeError` and the provider shows it as its error state (row 20). Wrapping it would turn a configuration error into a `TypeError` thrown inside the stop path.
10. **React's error context stays private; Vue's key is exported.** `useLiquidError()` is the React API (an error context has no use outside the provider; `LiquidContext` stays exported as before). Vue exports `LiquidErrorKey` like `LiquidKey`, since `inject()` needs the key for an app that provides its own refs.
11. **A stop during `create()` is reported before `create()` resolves.** `buildRuntime` grows the world right after `loop.start()` (W81 ward review m1); a throwing `resize_world` there stops the instance and calls `onError` while `create()` still runs, then `create()` resolves with the stopped instance. The providers mark the stop and destroy the instance on arrival (row 8 for the core order, 23 for React).
12. **The over-budget check tolerates rounding at equality.** A hinted budget is `particles · cell² / 2` with `cell = √(4A/N)`, i.e. exactly `2A`; an app whose later elements double its first batch's area reaches it exactly, and `max_area_px2()` came out a rounding error below the area in the plan validation (W74's `text-runtime.test.ts` atlas test, two equal buttons, warned "13440 px² exceeds the particle budget 13440 px²"). The check becomes `area > budget · (1 + 1e-6)` for every core (hinted ones too: a W84 threshold moves by one part in a million, which only matters at exact equality); a real overrun still warns (row 15 pins both: two 140 × 48 boxes on 1024 particles reach exactly 13 440 px² without a warning, and the plan validation's mutation without the slack makes row 15 fail). It changes a W84 warning threshold, so it is put to Dennis explicitly at the red STOP.

/// The acceptance elements and the batch's redistribute.
fn place(c: &mut FluidCore) {

    }
    c.redistribute();

    for f in 0..FRAMES {
        if f == SPLASH_FRAME {
            c.splash(CARD as u32, 640.0, 430.0, 1.0);
        }
        frame(c);
    }
}

fn bits(v: &[f32]) -> Vec<u32> {

        g.margin_px.to_bits(),

        g.origin_y_px.to_bits(),
    )
}

export const LiquidPlugin: Plugin<[LiquidOptions?]> = {
  install(app: App, config?: LiquidOptions) {
    const instance = ref<LiquidDOMInstance | null>(null);
    const error = shallowRef<unknown>(null);
    app.provide(LiquidKey, instance);
    app.provide(LiquidErrorKey, error);

    if (typeof window === "undefined") return;

    let unmounted = false;
    // The "app.unmount() BEFORE create() resolved" path is handled in createInto (destroy on arrival).
    createInto(config, instance, error, () => unmounted, "LiquidPlugin");

    const origUnmount = app.unmount.bind(app);
    app.unmount = () => {
      unmounted = true;
      // Race-symmetric destroy: handles "app.unmount() AFTER create() resolved".
      // The "BEFORE create() resolved" path is handled in createInto. Both
      // branches are required for full cleanup coverage.
      instance.value?.destroy();
      instance.value = null;
      origUnmount();
    };
  },
};

/** Read the live instance from injection. Null ref outside a provider/plugin and once the instance stopped. */
export function useLiquid(): Ref<LiquidDOMInstance | null> {
  return inject(LiquidKey, () => ref<LiquidDOMInstance | null>(null), true);
}

/**
 * W85 (D85-2): `Ref` of the error that left the provider (or the plugin) without an instance: a
 * stop's error (the instance is destroyed) or the create() rejection; null otherwise and outside a
 * provider. No retry: remount the provider (`v-if`, `key`) to create a new instance.
 */
export function useLiquidError(): Ref<unknown> {
  return inject(LiquidErrorKey, () => shallowRef<unknown>(null), true);
}

/** Element options (viscosity, recovery, drag), captured once at setup (D66-4). */
export type UseLiquidRefOptions = ElementOptions;

/** W85 (D85-3, design resolution 8): every own key whose value is defined; none → undefined. */
function pickElementOptions(opts?: ElementOptions): ElementOptions | undefined {
  if (!opts) return undefined;
  const out: Record<string, unknown> = {};
  for (const [key, value] of Object.entries(opts)) if (value !== undefined) out[key] = value;
  return Object.keys(out).length === 0 ? undefined : (out as ElementOptions);
}

/**
 * Template-ref composable: auto-observes when both element and instance are ready.
 * `flush: "post"` so the watch fires after Vue's DOM commit. Options are read
 * once at setup; changing a bound prop later has no effect (v1 limitation).
 */
export function useLiquidRef<T extends HTMLElement = HTMLElement>(opts?: UseLiquidRefOptions): Ref<T | null> {
  const instance = useLiquid();
  const elRef = ref<T | null>(null) as Ref<T | null>;
  const elementOptions = pickElementOptions(opts);

  watch(
    [elRef, instance],
    ([el, inst], _prev, onCleanup) => {
      if (!el || !inst) return;
      inst.observe(el as T, elementOptions);
      onCleanup(() => {
        inst.unobserve(el as T);
      });
    },
    { flush: "post" },
  );

  return elRef;
}

export const LiquidElement = defineComponent({
  name: "LiquidElement",
  inheritAttrs: false,
  props: {
    as: { type: String, default: "div" },
    viscosity: { type: Number, default: undefined },
    recovery: { type: Number, default: undefined },
    // W85 (D85-3): `default: undefined`, since Vue casts an absent Boolean prop to false.
    drag: { type: Boolean, default: undefined },
  },
  setup(props, { slots, attrs }) {
    const elRef = useLiquidRef<HTMLElement>({ viscosity: props.viscosity, recovery: props.recovery, drag: props.drag });
    return () => h(props.as, { ...attrs, ref: elRef }, slots.default?.());
  },
});

## When the liquid stops

If the instance stops for good (a frame that throws, for example), the provider destroys it: the elements are restored, `useLiquid()` returns `null` and `useLiquidError()` returns the error. A `create()` that rejects (no WebGPU with `renderer: 'webgpu'`, a WASM load failure) sets the same error. There is no automatic retry; remount the provider (a new `key`) to try again. Your own `config.onError` is still called.

```tsx
function Status() {
  const error = useLiquidError();
  return error ? <p role="alert">Liquid stopped: {String(error)}</p> : null;
}
```

`<LiquidElement drag={false}>` (or `useLiquidRef({ drag: false })`) opts an element out of every drag; like `viscosity`, it is read once.
