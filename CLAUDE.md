# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Identity

`liquiddom` puts WASM-driven **fluid dynamics** (2D MLS-MPM) on real DOM elements via a hidden `<canvas>`, preserving a11y. Rust computes the fluid on the CPU; TypeScript observes the DOM, runs the frame loop and renders. They share pre-allocated `Float32Array` views in WASM memory; there is no JSON over FFI.

npm workspaces: `packages/*` (`liquiddom`, `@liquiddom/react`, `@liquiddom/vue`, all `0.3.0-alpha.x`, fixed changeset group, pre mode `alpha`) and `examples/*`. `site/` is **frozen** (not a workspace, not in vitest or CI, `deploy-site.yml` is `workflow_dispatch` only) until slice 6. One Rust crate at the repo root produces `pkg/`.

## Architecture (high-level)

### Fluid engine (in progress, Epic 15)
The soft-body engine (W6–W62) is retired as of W66; its last state is the git tag `softbody-final`. The binding design is `docs/superpowers/specs/2026-10-02-liquiddom-fluid-design.md`. The canonical acceptance scene and slice matrix are in `.wdd/NORTH-STAR.md`. Slice 1 (W63–W66) ships the liquid at rest through the public API; slices 2–6 follow the matrix.
- `FluidCore` (`src/fluid/api.rs`, wasm-bindgen) is the only exported Rust class. `FluidBridge` (`ts/src/fluid-bridge.ts`) is the sole owner of its pointers and views.
- Strides (`src/fluid/layout.rs` ↔ `ts/src/fluid-layout.ts`, asserted equal by a test): `ELEMENT_STRIDE = 10`, `STATE_STRIDE = 4`, `DYNAMIC_FIELDS = 7`, `STATIC_FIELDS = 3`.

### Rule of Two
- **Rust is DOM-blind and colour-blind** (`src/fluid/`): particles, grid, element targets, rest state.
- **TypeScript owns DOM and render** (`packages/core/ts/src/`): `ElementRegistry` measures rects and writes the element buffer; renderers read the particle views.

### FFI contract
- **Element buffer**, 10 floats per element (TS writes):
  - `x, y, w, h` in buffer space (`w == 0` means inactive)
  - `radius_px`
  - `interaction` (0 idle, 1 hover, 2 focused, 3 dragged)
  - `home_dx, home_dy`
  - `viscosity` (NaN = default), `recovery` (NaN = default)

  **Element id == slot index.**
- **Dynamic view** (Rust writes every tick): SoA `x, y, f00, f01, f10, f11, flags` (`flags` value 1 `FLAG_TORN`, value 2 `FLAG_PARKED`, W81). Take a fresh view every frame.
- **Static view** (Rust writes at redistribute): SoA `home, rest_u, rest_v`. Read it only when `generation()` changes.
- **State view**: 4 floats per element, `s, maxDev, restAlpha, maxFDev` (slot 3 = max ‖F − I‖, W74).
- **Scalar calls:**
  - `tick(raw_dt_s, px, py, pvx, pvy, pointer_active, gx, gy)`. Rust owns the accumulator: 100 ms clamp, at most 3 × 1/60 s, 8 substeps each.
  - `splash`, `shake`, `set_material`, `redistribute`, `generation`, `set_reduced_motion`, `scroll_shift(dx, dy, ivx, ivy)` (W80: before `tick`, see Scroll), `resize_world(w, h)` (W81: outside `tick`, see Parking and resize), `set_viewport(w, h)` (W82: outside `tick`, see Under the page), `seed_gravity(gx, gy)` (W83: right before a frame's `tick`, see Gravity and tilt).
- The constructor is `FluidCore(particles, maxElements, worldWPx, worldHPx, areaHintPx2, maxElementHPx, seed)` (frozen in D64-4). `maxElementHPx` is the tallest initial element and sets the grid margin `max(200, maxElementHPx)` px.

### Internal runtime and public facade
- `runtime.ts` `createFluidRuntime()` (internal) sets up:
  - the canvas (`stylesheet.ts` `mountLiquidCanvas`)
  - the backend (single-flight `wasm-loader.ts`; jsdom uses the `@internal` `testBackend`)
  - the `ElementRegistry`
  - the renderer (`renderers/select.ts`)
    - W72: the renderer slot and the canvas are mutable (`runtime.canvas` and `activeRenderer` are getters). An `'auto'` fallback remounts the canvas in place (`remountLiquidCanvas`); a lost WebGPU device (any loss our own `destroy()` did not cause, keyed on device identity, not the reason string) rebuilds the instance as Canvas2D on a remounted canvas with the same core, one `console.warn` (`DEVICE_LOST_WARNING`), `activeRenderer` `'canvas2d'`. A failing rebuild takes the failed-frame path. `@internal` seams for the scene hooks: `simulateDeviceLoss()`, `fragmentEstimate`, `t0Size`.
  - the `LoopController` (user pause vs hidden tab)
  - reduced motion
- Per frame: coord offset → `applyDomChanges()` → `scrollTracker.sample()` (+ `placeCanvas`, `dragTracker.scrolled`) → `dragTracker.frame()` → `registry.sync()` → `core.scroll_shift()` (only when something scrolled) → `core.tick()` → `bridge.syncGeneration()` → `renderer.render(frame)` → `syncText` → `syncAway` → `syncHalo`. Under WebGPU (W74) the text atlas is rebuilt before the paints on a generation or paints change; the `liquid-text`, `liquid-away` (W78) and `liquid-halo` toggles run after `render()`, in that order. The first frame that throws stops the instance for good (one `console.error`, the loop is destroyed); recovery is `destroy()` + `create()`. `destroy()` never throws (a failing `core.free()` only warns).
- `index.ts` `LiquidDOM.create()` is the public facade:
  - `resolveOptions`: a whitelist; removed options throw. `silentFallback` hides the one `console.info` of an `'auto'` fallback (W72). The `@internal` hooks are `testBackend`, `loader`, `clock`.
  - autoObserve candidates become the area hint.
  - post-destroy semantics.
- `internal.ts` `runtimeOf()` serves the demo scene hooks only.
- Exports: `LiquidDOM`, `WebGPUUnavailableError`, `LiquidWasmLoadError`, `validateMaterial` (@internal), and the types `LiquidOptions`, `LiquidDOMInstance`, `ElementOptions`, `Material`, `GravityOptions`.

### DOM and a11y
- On `observe()` the colours are snapshotted **before** `class="liquid-element"` is applied. `data-liquid-stack="relative" | "z"` (the D7 stacking rules) is written only for an instance in the `z-index: 0` fallback (W82, see Under the page).
- One refcounted `<style id="liquiddom-styles">` per document, in `@layer liquiddom` with `!important`. The paint and stacking rules are scoped to `@media screen and (forced-colors: none)` and there is no `revert-layer`. Print and `forced-colors: active` hide the canvas, and the elements keep their own styling.
- The sheet also holds one halo rule per observed element (W75, D75-3): `.liquid-halo[data-liquid-id="h<n>"] { text-shadow: 0 0 1px C, 0 0 2px C, 0 0 4px C, 0 0 8px C !important }` with C the snapshotted background, in the same layer and media scope. `data-liquid-id` is document-unique (never the slot id) and restored on the last release.
- The canvas is `aria-hidden`, `pointer-events: none`, `z-index: -1` (W82; `0` in the fallback), last in `body` or inside the container. `unobserve()` restores the element exactly. Two instances observing the same element share one decoration (refcounted).
- Colours follow the DOM (W75, D75-1/2): one `MutationObserver` per observed element (`childList`, `characterData`, `subtree`, `style`/`class` with old values; per node and attribute only the batch's first old value is compared with the value now, `class` without liquiddom's own classes, so the `liquid-text`/`liquid-halo`/`liquid-away` toggles and the snapshot never loop) plus `transitionend` for `color`/`background-color` on the element re-snapshot colours on the next frame. Amendment B: only the element's own `class`/`style` re-reads colours (a descendant's re-renders the atlas only), the automatic re-read waits while a CSS transition runs or is paused on the element (`@keyframes` never block) and while it is detached, and the halo rule is rewritten only when the background changed; a manual `refresh(el)` runs at once. A `background-color` transition never runs on a decorated element (its background is held transparent), so `:hover` background changes still need `refresh(el)`. `refresh(el)` stays for changes elsewhere (a new stylesheet rule, an ancestor class without a colour transition). The snapshot lifts `liquid-element` with inline `transition: none !important`, flushes style, then restores the exact `class` and `style` attribute strings; `liquid-text` needs no lift (its rule never sets `color`).
- `liquid-text` (W74, D74-6): `.liquid-text, .liquid-text *` hide glyphs with `-webkit-text-fill-color` (`color` stays). The runtime sets it after `render()`, refcounted per element across instances, only under WebGPU while the renderer draws the element's atlas text (`textReady`) and its `restAlpha < 1`; it removes it on Canvas2D, reduced motion (at once), a lost device, a failed frame or rebuild, `unobserve` and `destroy`. The text atlas (`renderers/webgpu/text-atlas.ts`, D74-5) is built by the runtime, never the renderer.

### Renderers
- `renderers/frame.ts` defines `Renderer` (`init / render / resize / destroy`) and `RenderFrame`.
- `FluidCanvas2DRenderer` draws a density grid (cell `max(2, ceil(R)/6)` px for the largest kernel radius R (W82, D82-4; W77 had `/4`), never coarser than the finest particle spacing; paints without particles are skipped; W77) plus an exact `roundRect` at `restAlpha = 1`; while `restAlpha < 1` the density is splatted at full weight and the roundRect is drawn at `restAlpha` on top (D70-4, no translucent dip). It skips a particle that carries `FLAG_PARKED` or whose slot is inactive (w == 0; W81). No liquid text. While an element moves under Canvas2D the runtime sets `liquid-halo` on it (W75, D75-3; never under WebGPU, never under reduced motion), so its DOM text keeps a backdrop in its own background colour.
- `WebGPURenderer` (`renderers/webgpu/`, W71) draws the liquid in two passes: splat (instanced quads into T0 `rgba16float` = Σw·rgb, Σw and T0a `r16float` = Σw·a, additive, at `t0Scale` × the backing size, default 0.5, D71-4) and screen (composite: threshold 0.5 with an `fwidth` edge, colour Σw·rgb/Σw premultiplied by coverage·Σw·a/Σw; then a rounded-rect SDF quad per element at `restAlpha`, D71-6). `gpu-buffers.ts` packs the views (homes only on a generation or paints change); `kernel-params.ts` holds the kernel shared with Canvas2D (D71-5; 2.3 × spacing, cap 16 px since W77, D77-1). W74 (D74-4): while an element with atlas text moves, a third pass splats its text into T1 `rgba16float` + T1w `r16float` at 1× the backing (the liquid's kernel, `‖F⁻¹‖ ≤ 2`, coverage 0 when torn, degenerate or outside the rect) and the screen pass draws the text composite after the rest SDF; W79 (D79-1) adds the id target T1id (`rg16float`, min blending) to the text pass and drops the text where two element ids meet; the particle record is 32 B (`x, y, F, flags`), rest UVs upload with the homes, the atlas page once per version, ready only once its validation error scope resolves clean (W74 review). T2 is dropped. `'auto'` (the default) is WebGPU on a hardware adapter and Canvas2D otherwise: `WebGPUUnavailableError` (including an unusable presentation surface, checked in its own validation scope around `configure()` + `getCurrentTexture().createView()`) or a fallback (software) adapter → Canvas2D on a remounted canvas, one `console.info` unless `silentFallback` (D72-1). Explicit `'webgpu'` accepts a fallback adapter (SwiftShader) and rejects with `WebGPUUnavailableError` when unavailable (D72-2). Any other init error rejects `create()`. A device lost during init counts as unavailable. The renderer never warns; it reports a loss through `onDeviceLost` (never for our own `destroy()`). `renderers/webgpu/overdraw.ts` estimates splat fragments per frame (D72-4, logged via the hook `overdraw` and `perf-webgpu.json`, never gated). A text, colour, font or DPR change calls `textAtlas.invalidate(id)` in the runtime (W75); the runtime rebuilds the atlas and the paints in that frame before `render()` and renews the element's paint owner, so the confirmed old page masks it and its DOM text shows until the new page is confirmed (D75-1 amended); at most one atlas upload is in flight (B: a newer rebuild waits for the confirmation, changed slots carry no atlas rect meanwhile); no frame draws stale glyphs.

### Pointer, hover and material (Ward 068)

- **Soft pointer field (Rust, `interaction::pointer_accel`):** velocity-only coupling inside 70 px, weight `(1 − d/r)²`, 12/s (`POINTER_DRAG_PER_S`, D70-3; W68 started at 6), added after the home-spring saturation. No radial term; a resting pointer only damps moving liquid (−v·k), so it digs no holes. `PointerField::sanitized` (once per `tick`) turns NaN/Inf into an inactive pointer and clamps the speed to 2000 px/s.
- **Pointer input (TS, `pointer-tracker.ts`):** document `pointermove`, document `pointerout` with `relatedTarget === null` (left the window; D68-7 amended), `pointercancel`, touch `pointerup`, and window `blur`. Velocity is sampled per frame from the runtime clock (`0.5·v + 0.5·Δpos/Δt`, held ≤ 120 ms, then ×0.8 per 1/60 s: `idleDecay(Δt)` = `0.8^(Δt·0.06)` with the exponent snapped to 1 within 1e-9, so a 60 Hz frame is exactly ×0.8 and 120 Hz has the same tail in wall time; W84, D84-3, closing D68-4's limitation), so `?clock=manual` is deterministic.
- **Hover (D68-2 amended):** `pointerenter`/`pointerleave` on the observed element, ignoring `pointerType === "touch"` (a tap's compatibility `mouseenter` would stick); the initial `:hover` is read at observe only under `(hover: hover)`. The registry writes slot 5 every `sync()`: dragged (3, W78) beats hover (1) beats focus (2) (a click focuses buttons in Chrome/Firefox and must not drop the swell; FOCUSED has no engine effect yet), idle (0). Hover is also cleared when the element is detached or `:disabled` at `sync()`. The home rect swells by `HOVER_SWELL = 0.02` about its centre, radius included (`swell_rect` in Rust, called from `home_rect`; the same rule in TS `homeRect`).
- **Reduced-motion input gating:** pointer inactive and slot 5 = 0. The runtime's `splash` returns `true` without calling the core (so the facade does not throw), and `shake` returns early. Validation still runs. It follows live media changes.
- **Fused AABB (D68-10):** redistribute, the reduced-motion pin, splash, shake, an active pointer tick and `set_particle_px` call `Scratch::invalidate_bounds()`, so `SubstepOpts::reuse_bounds` never reuses a stale particle AABB.
- **Material:** `setMaterial(partial)` snapshots the partial once (getters read once), then runs `validateMaterial` → `mergeMaterial` → `core.set_material` → assign, atomically; `getMaterial()` returns a copy. `presets` = `water`, `honey` (`viscosity` 0.9, `cohesion` 0.7, `recovery` 0.8; re-forms within 3 s, W77), `jelly` (material-shaped; the 0.2 physics presets are gone).

### Drag and merge (Wards 078–079)

- **Gesture (TS, `drag-tracker.ts`, one per instance):** a mouse or pen `pointerdown` with the primary button on an observed element (the innermost one) becomes a drag once the pointer is more than 4 px away; only then is the pointer captured. `active = {el, dx, dy}`; `registry.sync()` writes slot 5 = DRAGGED and slots 6–7 = `dx, dy` for it, 0 for the others (and 0 under reduced motion). Release: `pointerup`; cancel: `pointercancel`, blur, Escape, `lostpointercapture`, a move with the button up, `unobserve`, `destroy`, reduced motion, a detached element, a lost device, a failed frame. The click that ends a drag is swallowed once at the window's capture phase (D78-6). While a press is live, `selectstart`/`dragstart` are prevented. The keyboard never drags; touch drags after a long-press (W84, see Touch and opt-out).
- **Engine (Rust):** `interaction::hold_dragged` runs `damage(id, 0.5)` for a dragged element every substep after `update_stiffness`, so it never rests (D78-5); `update_velocities` adds the offset delta while dragged (the release frame adds none); the soft pointer field skips the dragged element's particles (D78-4). The saturated home spring brings it home after release.
- **Label:** WebGPU's atlas text rides the liquid; under Canvas2D `away-toggle.ts` holds `liquid-away` (the `liquid-text` declarations under their own class) while dragged and after release until restAlpha is 1, refcounted across instances; a cancel releases it at once; held elements get no halo (`HaloSyncArgs.suppressed`).
- **Merge (W79, D79-2):** `hold_dragged` also gives every active, non-dragged element whose home rect overlaps the dragged home rect grown by 16 px (`rects_overlap`, open intervals) `damage(id, 0.2)` every substep. The dragged element and those neighbours carry `Elements::merge_slip` until their restAlpha is 1 again (also cleared on `reset_slot`, reduced motion and an inactive slot); `ElRow` then slips them at 4.5/s, 240 px/s instead of 3/s, 160 px/s, so without a drag the engine is bit-identical to W78.
- **Labels never overlap (W79, D79-1):** the WebGPU text pass writes `(id, −id)` of every text-splat fragment (coverage 0 included) into T1id (`rg16float`, `min` blending, cleared to 4096); the text composite gathers the 2×2 neighbourhood of its bilinear sample and gives the text coverage 0 where the smallest id is below the largest, so there is a text-free band up to one kernel radius (≤ 16 px) where two moving text liquids' kernels overlap. `captureTextIds()` (`@internal`, renderer and runtime) reads T1id back for the acceptance hook `__liquidTest.textIds()` only.

### Scroll (Ward 080)

- **Tracker (TS, `scroll-tracker.ts`, one per instance):** once per frame after `applyDomChanges()` it reads the window's `scrollX/Y` (body) or the container's `scrollLeft/Top` and returns Δ since the last frame (0 on an instance's first frame; a canvas remount does not reset it; a non-finite read or a detached container is unusable: Δ 0, the last good position is kept), the inertia `Δ · 60 · SCROLL_INERTIA` (0.02) capped at `SCROLL_INERTIA_MAX_PX_S · dt · 60` (30 px/s per 1/60 s, dt up to 100 ms; 0 under reduced motion and on a frame without elapsed time; D80-2 amended) and `dragDx/dragDy` (Δscroll − Δoffset). The runtime calls `core.scroll_shift(dx, dy, ivx, ivy)` after `registry.sync()` and before `tick`, only when something scrolled. Container mode: `placeCanvas()` writes `transform: translate(scrollLeft, scrollTop)` on liquiddom's canvas (on change only; also after a device-loss remount), so it sits on the container's visible window; a page scroll around a container shifts nothing.
- **Engine (Rust, `scroll.rs`):** `ScrollShift::sanitized` (NaN/Inf → 0, ±`WORLD_MAX_PX`, inertia ≤ 2000 px/s, 0 under reduced motion); `apply` moves every particle of an element that `shifts_with_scroll` (not dragged; W81: not parked) and whose rect moved with the scroll (`moved_with_scroll`: its rect change `m` since the last velocity sample satisfies `|m + Δ|² ≤ |m|²`, i.e. at least half the scroll against it; no sample yet → follows; skipped under reduced motion, where the pin decides; ward review I1) by whole cells and the grid's lattice origin by the rest (`Grid::scroll_origin`, within half a cell of `−margin`), so the simulation equals the unscrolled one up to f32 rounding; those particles gain the inertia; `Elements::shift_prev` moves the previous home rect so the home velocity sees no scroll; `invalidate_bounds()` (D68-10). A `position: fixed` element (or one in a fixed ancestor) and a stuck `sticky` one are not shifted: their liquid stays put in px like a dragged one's; a sticky element switches per frame.
- **Drag:** a dragged element is not shifted; `DragTracker.scrolled` adds the scroll to the press's offset (a press below 4 px accumulates it; a scroll alone never starts a drag), so the dragged liquid stays under the pointer. The runtime calls it only when the pressed element moved with the scroll (`registry.movedWithScroll`: one rect read of that element against the rect the last `sync()` wrote, the same rule as Rust's), so a press on a fixed element keeps its offset.
- **Known:** the canvas can trail a native scroll by one frame (D80-4): invisible at rest, but while scrolling the DOM labels can sit 60–100 px off their liquid for one frame per scroll step in both renderers (a canvas that scrolls with the content is the known alternative); an element that leaves the world plus the grid margin only partly keeps its wall-clamped liquid until it parks or re-forms (W81); under continuous scrolling a re-entered element leaves rest through W80's scroll inertia (D80-2) like any other, it re-enters at rest; in container mode the translated canvas keeps the container's scroll range after its content shrinks.

### Parking and resize (Ward 081)

- **Parking (Rust, `parking.rs`):** an element whose home rect lies entirely outside the world plus the grid margin (`max(200, tallest initial element)` px, where the walls sit) is parked: its particles carry `FLAG_PARKED` (value 2 in the dynamic view's `flags`), skip P2G, the grid update, G2P and the particle AABB, `scroll_shift`, splash, shake and the merge damage, and the element is held at rest. It unparks once its home rect lies 64 px inside the bound on every side or overlaps the world (D81-1); in that tick (also a 0-step one) its particles are placed at rest (`home + rest_uv`, v = 0, C = 0, J = 1, F = I) and it has no previous rect sample, so it shows at rest the frame it re-enters. A dragged or inactive element is never parked. A parked element keeps its particle share; its particles count as unplaced, so a redistribute places one that gets a new home on its new target. `parking::update` runs first in every `tick` and after `pool::redistribute`; `sync_particles` runs once after a redistribute. A parked element whose slot goes inactive (w == 0) without a redistribute has its particles' kinematics reset when they lose the flag.
- **Renderers:** Canvas2D skips a particle with `FLAG_PARKED` and every particle of an inactive slot (w == 0, as WebGPU's element record does); WebGPU packs a parked particle off-screen (`packParticles`).
- **Resize (D81-2, D81-3):** the runtime keeps the core's world (`world.ts`: body `max(screen, inner)`, container the client box, Rust's clamp mirrored). `resizeCanvas()` (window `resize` / the container's ResizeObserver) grows an outgrown axis to max(need, ⌈1.25 × current⌉), capped at 8192 px, and calls `core.resize_world(w, h)` once (also on a DPR change and after a device-loss rebuild; never inside a frame, never before the loop starts, not after a failed frame; one call right after `loop.start()` covers a window that grew during init) with one `console.info`. `resize_world` reallocates only the grid arrays (cell, margin and lattice origin kept, so W80's lattice phase holds); it never shrinks. `FluidRuntime.world` (@internal) reads the copy. `world` is assigned only after success; a throwing `resize_world` stops the instance like a failed frame (shared `stopInstance(msg, err)`; one `console.error` "[liquiddom] growing the fluid world failed; the instance stopped. Call destroy() and create a new instance.").
- **Known:** `resize_world` sizes the grid from world + margin; a margin near 8192 px at a 4 px cell would need ≈ 450 MB (the default 200 px margin: ≈ 55 MB at an 8192 px world).

### Under the page (Ward 082)

- **Stacking (D82-1 … D82-3, `stacking.ts`):** the canvas mounts at `z-index: -1` (`CANVAS_Z_UNDER`), so every page box and its text paint above escaped liquid, and no observed element needs the D7 rule. `createFluidRuntime` checks first (`canvasBlocker`): in container mode the container must be a stacking context (`formsStackingContext`: `isolation: isolate`, a `z-index` on a positioned box, a transform, …); in body mode `<body>` must not have a background while `<html>` has one. Every fresh `observe()` walks the element's ancestors up to the container or `<html>` (`opaqueAncestor`: any alpha > 0 or a `background-image`, where a multi-layer `none, none` counts as none; `<body>` only when `<html>` has its own; an observed `.liquid-element` never counts). The first hit gives one `console.warn` (`CONTAINER_STACKING_WARNING`, or `OPAQUE_BACKGROUND_WARNING` naming the element and the fix) and the instance falls back for good: its canvas goes to `z-index: 0` (`CANVAS_Z_FALLBACK`; `remountLiquidCanvas` keeps the old canvas's z-index) and every element it observes holds `data-liquid-stack` (`holdStacking`/`releaseStacking`, refcounted per element across instances; the sheet text is unchanged, the D7 rules key on the attribute). liquiddom never restyles the container, `<html>` or `<body>`.
- **Viewport edge (D82-5, `viewport.rs`):** the runtime sends the visible window (`innerWidth × innerHeight`, or the container's client box; buffer px) with `core.set_viewport(w, h)` before the first frame and from `resizeCanvas()` whenever it changed (never in a frame, never after a failed one). `shake` mirrors the outward component of an element's direction when its home rect lies within `EDGE_MIRROR_PX` (80) of a viewport edge (per axis; near both edges of an axis: unchanged); every other element, and every core before the first `set_viewport`, is bit-identical to W81.
- **Known:** a background added to an ancestor after `observe()` is not re-checked; a `<body>` that is itself a stacking context still falls back when `<html>` and `<body>` are opaque (harmless); an ancestor stacking context with a negative `z-index` is not detected (the canvas at −1 can paint over its text); ancestors outside a shadow root's host are not walked; under the page, muted page text over dark liquid is low-contrast while the liquid passes; "Book a demo" on the landing page beads for ≈ 5 frames under a shake (D82-6, accepted).

### Gravity and tilt (Ward 083)

- **Engine (Rust, `gravity.rs`, D83-1, D83-2):** a per-core low-pass `g_lp` (f64, `τ = 0.5 s`, advanced once per fixed step); each fixed step hands the grid `GRAVITY_SCALE · (g − g_lp)` (1.5, clamped to `GRAVITY_CLAMP_PX_S2` 2000 along its direction) through `Grid::set_body_accel`, and `update_velocities` adds it to the cells with mass after momentum → velocity, before the walls and the CFL cap. Below `GRAVITY_SNAP_PX_S2` (0.5) the high-pass snaps to exactly 0 (`g_lp = g`), so ≈ 8τ after a change the engine is bit-identical to one without gravity. Input is sanitised (NaN/Inf → 0, ±1e5). Under reduced motion `tick` seeds the low-pass every call. Parked particles skip the grid; the home spring is unchanged (a subtle lean, ≈ 6.4 px for a 90° tilt, rest within 3 s).
- **Sources (TS, `gravity.ts`, D83-3 … D83-5):** `GravityInput` (one per instance) gives every frame's `tick` its gravity: `none` 0; `fixed` `normalize(vector) · strength` (a zero vector is none); `orientation` the device direction from `deviceorientation` β, γ, `(cos β · sin γ, sin β)` rotated by `screen.orientation.angle` (else `window.orientation`, else 0), times `strength`, held until a reading turns it by more than `ORIENTATION_DEAD_BAND_DEG` (2), with the listener only while the source is `orientation` (removed on a switch, on `destroy` and when `stopInstance` stops a failed instance). Under reduced motion it hands 0. It asks for `core.seed_gravity` before the tick at `create()`, after a source switch, on the first orientation reading and on the first frame after reduced motion, so none of them sloshes (D83-4).
- **API (D83-3):** `setGravity(partial)` reads each own key once (`mergeGravity`), validates the merge like create()'s `gravity` (TypeError, state unchanged) and hands it to the runtime; a change within a source acts on the next frame.
- **Known:** the effect is a subtle lean by design (a bigger slosh would need a softer spring during a tilt); `requestOrientationPermission()` is untested on an iOS device.

### Touch and opt-out (Ward 084)

- **Long-press (TS, `drag-tracker.ts`, D84-1):** a primary touch `pointerdown` on a draggable observed element (the innermost one) starts a real `LONG_PRESS_MS` (350) `setTimeout`; the finger's own motion past `TOUCH_SLOP_PX` (8), `pointerup` (a tap stays a click), `pointercancel`, blur, Escape, `unobserve`, `destroy`, reduced motion and a detached element end the press, and every end clears the timer. When it fires the press drags like W78's (DRAGGED, pointer capture, the ending click swallowed, except after a slow tap: a touch drag released within 8 px of where the finger rested with no scroll since the down point lets its click pass, ward review I1), starting at the finger's offset (0, 0) plus the scroll since the down point (the down point moves to where the finger rests). A non-primary pointer is never a press. Every draggable observed element carries one non-passive `touchmove` listener from `observe()` to `unobserve()`/`destroy()` that calls `preventDefault()` only while a touch drag is live (W84.0 Q1 (a): the only strategy present at `touchstart`, which iOS Safari needs; its cost: a swipe starting on an observed element waits for the main thread). `onLost` ends a drag only for the dragged element's own `lostpointercapture` (a touch's implicit capture on a child moves to it at the fire). No extra feedback (D84-4): W78's hold softens the liquid from the first frame.
- **Menu and callout (D84-5):** while a touch press is live (pending or dragging) the document `contextmenu` is prevented; a mouse right-click is never touched. The sheet's `.liquid-element:not([data-liquid-drag="off"]) { -webkit-touch-callout: none }` (screen + forced-colors: none) covers draggable observed elements; a second rule, `.liquid-element[data-liquid-drag="off"] { -webkit-touch-callout: default }` (no `!important`), gives an opted-out element nested in a draggable one the browser's callout back, since WebKit inherits the property (it also beats an author's inherited `none`; a rule on the element itself still wins). The `contextmenu` listener is capture-phase.
- **Opt-out (D84-2):** `observe(el, { drag: false })`, validated and captured once with the registry record; the tracker attaches it opted out (it claims its `pointerdown`, so an observed ancestor never drags for it, and starts nothing: no mouse, pen or touch drag, no `touchmove` listener, no menu suppression). `holdDragMode`/`releaseDragMode` (refcounted per element across instances, with the decoration) keep `data-liquid-drag="off"` while every observing instance opted out; an element observed without the option gets no attribute.
- **Known:** iOS Safari, Android's real menu and the swipe latency are checked only on a phone (Chromium's emulation fires no `contextmenu` on a hold); the counter-rule is untested on iOS (the scene has no nested observed link); Windows/ChromeOS touchscreens likely fire `contextmenu` on lift, after `end()` removed the listener, so the menu can open after a touch drag there (unverified; ward review I2, Dennis 2026-10-21); the callout stays suppressed under reduced motion, where no drag starts; the touch e2e must never use `page.waitForFunction` or CDP `Log.enable` (both make the whole document a blocking touch region).
